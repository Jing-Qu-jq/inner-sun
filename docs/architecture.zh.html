系统架构 (System Architecture)

面向留学生的 AI 心理咨询助手。我们的差异化并不在于 AI 模型本身 (differentiator)——而在于一套自有的 关怀模式 (Care Patterns)知识库：由我们的研究员从真实临床案例中撰写、并以研究文献为依据的「特定学生情境 + AI 应采用的治疗策略」。AI 在对话中实时检索并运用这些专业知识。AI 是「引流的钩子 (hook)」；商业目标是建立足够的信任， 让学生预约一位真人咨询师 (human counselor) 的面谈。

👩‍💻 面向工程师 📋 面向产品经理 (PM) 📈 面向投资人
知识库以英文 (English) 撰写（研究员与文献引用统一使用同一种语言），而助手会用用户在界面上选择的语言回复—— 目前支持英文和简体中文，后续会增加更多语言。

通俗解释
学生的浏览器只会与我们自己的后端通信，绝不直接连 OpenAI。后端（即「编排器 (Orchestrator)」）是大脑：它判断学生 需要什么，查出最合适的、由研究员撰写的指导（一条关怀模式），让 OpenAI 用这种风格写出一段温暖的回复，做安全检查，并决定 何时建议预约真人。AI「知道」的一切都存在我们的数据库里，由我们的研究员掌控。虚线部分留待日后。
工程细节
编排器是一个轻量、无状态 (stateless) 的服务（Node + TypeScript，基于 Fastify）。把 OpenAI 调用放在它背后同时带来三点好处：安全 （密钥不进入浏览器——目前的原型会泄露密钥，我们会在 v1 修复）、成本可控（集中做缓存、模型分级、Token 上限）、 以及可移植性（模型供应商藏在同一接口之后——「用 OpenAI」只是一项配置，而非锁定）。

通俗解释
任何人都能即时、匿名地开始——这就是「树洞 (tree hole)」的承诺，也是漏斗的顶端。注册用户不仅会被记住历史，还有先发 优势：注册问卷会在他们打出第一个字之前，就预置一个初始的关怀模式匹配。常见问题（例如「这是保密的吗?」）用预写好的文字回答， 完全不调用 AI。对于真正的倾诉，我们会悄悄地把学生匹配到研究员的案例，运用相应指导，写出关怀的回复，做安全检查——只有在信任 已建立时，才提及有真人咨询师可预约。
工程细节
匹配是一个持续进行 (running) 的评估。对匿名用户，我们不会在第一句「hi」就匹配；而是等到有足够实质内容 （几条有实质内容的消息 / 一个较小的 token 阈值），再由相关性下限 (relevance floor) 决定是否真的套用某个模式。 对注册用户，问卷给出一个温暖的起点，再由对话逐步细化。危机检测是一条独立、更高优先级的通道——它绝不会引导 「下周预约」，而是立即给出即时资源。

关怀模式存在哪里：带 pgvector 扩展的 Postgres。一个托管数据库 装下所有东西——模式文本、向量、用户、记忆、预约、预设答案——并具备真正的事务与统一备份。 以我们的规模无需单独的向量数据库 (Pinecone/Qdrant/Weaviate)；pgvector 可轻松应对数万条模式，日后若量级需要再迁移。

托管方案：Supabase
于 2026-08-15 确定。本地开发用 Docker 的 pgvector/pgvector:pg16 镜像运行同样的数据库， 迁移脚本是纯 SQL，可在两者之间原样移植。Supabase 本就是架构默认的方向——schema 中的 users 表已预留了与其 auth.users 对接的考虑——因此在研究员后台工具需要托管时采用它， 意味着最终部署可以直接沿用这部分工作，而不必重做。

关怀模式字段 (schema, v1)：id/title · situation（情境，用于嵌入→匹配）· signals（信号）· strategies（策略，→提示词）· avoid（禁忌）· escalation（升级）· source_refs（研究文献引用）· locale notes · status（状态）。以英文撰写。

发布是一个明确的动作。一条模式会经历 draft（草稿）→ published（已发布）→ retired（已下线）三种状态，而只有已发布的模式才会被检索。新写的模式默认是草稿， 因此撰写本身不会把它推到学生面前，必须有人主动点击发布。这样默认状态就是无害的那一个： 一旦疏忽，结果是模式没有发布，而不是让一段没写完的内容出现在正处于困境的学生面前。 下线是一种软撤回，会保留记录、历史与恢复的可能——事后被证明有问题的临床指导，恰恰是最需要留痕的。

冷启动（两条入口）：

  • 注册用户 → 问卷。注册时的 5–8 道简短、温和、以选择题为主的问题，在用户档案上为初始的前 N 匹配预置数据。 要可跳过、低门槛（每多一题都会流失注册）；心理健康问卷属于敏感数据，须获得同意 (consent)。
  • 匿名用户 → 基于信号。当早期消息有足够实质内容时尝试首次匹配；由相关性下限决定是否套用。（不是死板地「数够 5 个 关键词」这种门槛——关键词/主题抽取只是喂给匹配的一个信号，而非硬性触发。）
工程细节
一条模式的向量在保存时计算一次并与该行一同存储——对话时绝不重算。新增第 200 条模式是纯粹的内容工作，无需改代码。 检索即 ORDER BY embedding <=> :query_vector LIMIT N。

「保存时算一次」有两个后果值得写明，因为它们都是静默失败，而不是报错。 没有向量的模式对检索而言是不可见的——这一行在任何数据库客户端里看起来都完全正常， 也不会有任何地方提示它检索不到。另外，不同嵌入模型产生的向量之间不可比较， 混用只会得出毫无意义的相似度分数，而不会报错。因此 schema 在向量旁边记录了来源信息： 由哪个模型生成、生成时间，以及一个标记该向量是否仍对应当前 situation 文本的标志位。 重新嵌入命令会清扫被标记的行，而校验脚本在仍存在此类行时会拒绝进行排序。

匹配到底是怎么工作的

关键认知
对话模型并不会「读」历史然后「挑」一个关怀模式。匹配是向量数学 (vector math)，不是 LLM 的推理。
  1. 构建紧凑的匹配查询——用运行摘要 + 学生最近的几条消息，并归一为英文。只取学生自己的消息： 若把我们的回复也放进去，等于把已经注入的指导又喂回「挑选指导」的查询里，模式会不断自我选中。最新一条消息会被 明确标注为最新，这样学生换话题时匹配会跟着走，而不会被他自己更早的几条消息盖过。
  2. 做嵌入 (embed)——text-embedding-3-small 把它变成约 1,536 个数字的向量。每条关怀模式的 situation 在保存时已用同样方式嵌入过一次。
  3. 向量搜索（即匹配）——pgvector 用余弦相似度 (cosine similarity)（0–1）比较，返回带分数的前 N 条。此步无 LLM。
  4. 相关性下限（即闸门）——最高分 ≥ 阈值 → 注入/融合这些策略；低于则进入通用共情模式并标记缺口。
  5. 每轮重复——随对话展开重跑，使匹配逐渐收敛或切换。

下限如何确定：它不是一个凭空的常数，也不是百分比——余弦相似度的绝对值既取决于所用的嵌入模型， 也取决于模式本身的措辞，因此这个下限是测出来的，不是拍脑袋定的。npm run retrieval:calibrate 会把带标注的样例（一类是「明显应当命中某条模式」的消息，一类是「知识库确实没有覆盖」的消息）跑过真实管线， 并打印出把两者分开的分数区间。

在 Feature 6 的起步模式集上、用 text-embedding-3-small 测得：正确命中的分数区间是 0.61–0.81， 未覆盖的消息则在 0.46 及以下，因此默认下限取两者的中点 0.54（CARE_PATTERN_RELEVANCE_FLOOR）。 本文早先的版本建议从 ~0.7–0.8 起步；实测表明，在这个知识库上那样会把每一条正确命中都挡在门外——而且是悄无声息地挡掉， 每条回复看上去都依然正常。模式集有较大变动时就该重新跑一次标定；如果两个区间出现重叠，说明没有任何阈值能把它们分开， 该改的是内容，而不是这个数字。gpt-4o-mini 的「评估」步骤是补充（抽取信号；未来的混合 (hybrid) 方案会对向量前 10 条做重排序 (re-rank)）——但 v1 的匹配就是「嵌入 + 余弦」。

语言：英文知识库，按用户语言回复

  • 知识库＝英文——统一的规范语言，与研究文献一致，模型在英文临床内容上表现最好；避免知识库出现翻译漂移。
  • 回复跟随界面语言——gpt-4o 是多语言的：它读英文策略，用英文或简体中文流畅作答（通过一句「用 {locale} 回复」的指令）。
  • 跨语言匹配——中文对话要匹配英文知识库。嵌入是多语言的，但跨语言召回较弱，因此在向量搜索前，我们用便宜的 gpt-4o-mini 把匹配查询归一为英文（英文→英文检索更可靠）。回复仍用用户的语言。在起步模式集上的实测： 归一化让 12 条命中样例的最高分全部上升，平均 +0.17；而且它对正确命中的提升远大于对未覆盖消息的提升—— 正是这一点把两个分数区间拉开，才使「设一个下限」成为可能。它还会把第一人称的倾诉改写成模式所使用的第三人称情境语言， 因此在英文对话上同样值回票价。

以研究文献为依据

我们有一些研究论文与文章。它们的角色是刻意设计的：

  • ✅ 主要用途——论文是研究员提炼成关怀模式的原料，并在 source_refs 中标注引用。每条策略都经过人工把关、 安全，且可追溯到同行评审的研究。
  • ⚠️ 要避免——把论文原文经 RAG 直接塞进咨询回复。学术文字是写给临床医生看的，直接检索会带来术语堆砌或误用结论——是安全隐患。
  • 🔵 未来——一个内部「研究文献库」（把论文切块 + 嵌入）作为研究员撰写/检索的辅助与引用来源，而非面向用户的运行时来源。

4预设答案 (FAQ) — 直接存，不要缓存 🟢

有些问题根本不需要 LLM：「这是保密的吗?」「怎么预约真人咨询师?」这些给出预写好的双语答案。

为什么不用缓存
缓存 (cache) 存的是昂贵的计算结果以免重算；而预设答案是人工撰写的常量——没有可重算的东西，也就没什么可缓存的。直接存起来即可。
  • v1 — 代码库里的 i18n / 配置文件。有版本管理、零基础设施，直接并入英文/中文文案表。
  • 之后 — 一张 canned_responses 数据表，当非工程人员需要不发版就能改答案时再迁移。

最佳体验：做成可点击的快捷回复气泡 (quick-reply chips)——每个气泡确定性地映射到它的答案：不调用 LLM、无需匹配逻辑、零成本。

5成本控制 (Cost Control) 🟢 （语义缓存 → 未来版）

每次对话约 $0.05，随规模增长真正要看的是单位成本 (unit cost)。按影响力排序的手段：

手段阶段作用
模型分级 (model tiering)v1用 gpt-4o-mini 做分类/安全/摘要；gpt-4o 只用于生成回复。最大的杠杆。
历史摘要 (summarization)v1把较早的对话摘要化，而非每轮重发；完整历史会呈平方级增长。
提示词缓存 (prompt caching)v1OpenAI 对不变的系统提示前缀按折扣计费。几乎零成本即可启用。
Token 上限 + 限流v1限定 max_tokens；防滥用，避免免费额度被刷。
语义缓存 (semantic cache)未来对重复的常见问题跳过模型调用。暂缓——对咨询帮助有限。绝不缓存个性化的情感回复。
参考数字
按 5 个用户 × 每天 1 次对话，一周约 $1.8（含这些优化）对比 $2.6（不含提示词缓存）。在此规模下绝对值很小；重点是 随规模放大时你要乘的那个 ~$0.05/次对话 的单位成本。

6商业模式 (Monetization)

核心的「树洞」倾诉保持免费——这是品牌承诺，也是漏斗顶端。把变现放在它周围。

AI 聊天有意作为低毛利的获客 (lead generation)——这正是成本手段重要的原因。真正的收入是真人面谈的预约 （高客单、可复购）。数据飞轮 (data flywheel) 会随时间不断加深护城河。

7为什么有护城河 (Defensibility)

  • 自有的临床知识库。竞品都是套在同样公开模型外的薄壳 (prompt-wrapper)；我们由研究员撰写、以真实案例为依据的关怀模式， 是模型不具备、竞品也复制不了的内容。
  • 可编辑、可追溯。专业知识存在数据库里（RAG），而非固化进模型权重（微调 fine-tuning）——研究员改一行即刻生效， 且每条回复都能追溯到经审核的来源材料。
  • 不断复利的数据飞轮。真实的（已获同意、去标识化的）对话会揭示接下来该撰写哪些案例。

8数据科学与大数据的定位 (Data Science)

核心观点
做核心匹配不需要预测型的大数据模型。电商推荐系统是从数百万用户的间接行为（点击、购买）中预测隐藏意图 （需要大数据，且有冷启动问题）。我们的匹配是基于内容的 (content-based)：学生用文字直接说出问题，所以匹配是 「理解 + 路由」到研究员撰写的知识库——从第 1 位用户起就能用，研究员的知识库替代了对数据网络效应 (data-network effect) 的依赖。电商那种预测模型对应到我们的未来版协同过滤层：是锦上添花，而非地基。

所以数据科学家的价值分两个阶段：v1＝搭建 + 分析（几乎不需要数据），而这正是解锁未来＝训练模型（需要积累的数据）的前提。

关于我们的真实医疗案例
真实医疗案例属于知识数据 (knowledge data)——非常适合用来撰写模式、构建评估集与标定（因此数据科学家能更早介入）。 但它们训练不了预测型模型（那需要上线后的行为数据），而且——最关键——它们是受保护健康信息 (PHI)： 在任何流水线接触之前必须去标识化，且绝不可把原始案例做成面向用户的检索索引。安全路径是：案例 → 研究员提炼 → 去标识化的关怀模式 → RAG。

节奏建议：规模很小时不要招数据科学家（没有可训练的数据）。把第 1–2 项做进 v1，让干净的数据等在那里。之后先从评估、 标定和危机分类器入手，再进阶到训练型的匹配/推荐模型。上线永远不会被机器学习卡住。

9未来规划 (Future Plan, v2+) 🔵

  • 语义缓存——对重复的常见问题跳过 LLM（仅限 FAQ；绝不用于个性化回复）。
  • 协同过滤（相似用户的智慧，"wisdom of similar users"）。幼稚做法「拿用户 A 的回复去答 B」不安全（泄露隐私；临床上有风险）。安全做法：让学习流经关怀模式层—— 挖掘相似用户的成功对话 → 去标识化的聚合规律 → 研究员审核 → 更新模式。用相似用户去推断新用户的模式，则是低风险的冷启动加速器。
  • 自动化飞轮——自动聚类低匹配对话并建议新的关怀模式。
  • 语气/风格微调——在积累数千条高质量对话后，微调一个更小的模型只负责语气（知识仍在 RAG）。
  • 订阅与支付、进阶记忆、加权意愿评分。

10硬性约束 (Hard Constraints)

  • 隐私与同意。敏感的心理健康数据，且很多来自中国公民。匿名日志需要清晰的告知；用对话来撰写模式需要单独、明确的同意 + 在任何人工查看前完成去标识化。中国的 PIPL（尤其跨境传输）、GDPR 及特殊类别数据规则都适用—— 在数据飞轮或协同过滤运行前，必须获得法务放行。从第一天起就设计好同意与日志。
  • 安全。带真实升级路径与资源的危机/自伤检测不是可选项。
  • 不是医疗器械。AI 提供支持与应对策略，绝不做诊断——超出其能力范围就转给真人。
